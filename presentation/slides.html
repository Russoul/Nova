Nova

An extensional proof assistant, for people who write programs and would like them to be correct.

Live in the editor · every snippet is real, checked Nova · Agda alongside at each step

Nova is a work in progress: the surface syntax you will see today is subject to change.

Part 0 · the thesis

Two ways to say "equal"

Intensional — Agda, Lean, Coq

a ≡ b is a data type. A proof of it is a value.

To use it you transport along it: subst, rewrite, cong.

Two functions with the same graph are not equal. Two streams with the same behaviour are not equal. A bag is a list plus a relation you promise to respect.

Extensional — Nova

a ≡ b is a proposition: a type with at most one proof, written ⋆.

A hypothesis h : a ≡ b is reflected: wherever it is in scope, a and b are interchangeable for the type checker.

Funext, proof irrelevance, UIP, computing quotients, coinductive equality: theorems or rules, not axioms.

The price: conversion is undecidable in general. The rest of the session is what Nova does about that.

Part 0 · the loop

What happens when you save

  1. You write a program or a proof. Holes ?name are allowed anywhere.
  2. Where the elaborator needs an equation it cannot see, it does not fail: it records an obligation and carries on.
  3. The report lists holes and obligations with their context, and usually a hint naming what would close each one.
  4. You close them by citing: a using (…) clause naming the lemmas and unfoldings the proof may use — or by adding a lemma above.
  5. Zero obligations → Accepted. A small trusted kernel replays everything.
-- start/Arith.nova, after one save
open holes (1):
  [?zr] (n : ℕ) ⊢ ?zr : plus n Z ≡ n ∈ ℕ
open obligations (1):
  [1] ⊢ plus 2 3 ≐ 5 : ℕ
      at: def twoPlusThree: checking ⋆
      hint: closes by citing plus.eq

No tactics, no search: what a proof cites is in the file. Think simp only [ … ], never simp.

Part 1 · the primer

Commutativity, both ways

Nova · Arith.nova

def plus : ℕ → ℕ → ℕ
  | plus Z m ≔ m
  | plus (S n) m ≔ S (plus n m)

def plusZr : (n : ℕ) → plus n Z ≡ n using (plus.eq) ≔
  λn. ℕ-elim ⋆ (k ih. ⋆) n

def plusComm : (n m : ℕ) → plus n m ≡ plus m n ≔
  λn. λm. ℕ-elim
    (plus Z m ≡⟨ plusZ m ⟩ m ≡⟨ plusZr m ⟩ plus m Z)
    (k ih. plus (S k) m
        ≡⟨ plusS k m ⟩ S (plus k m)
        ≡⟨ ih ⟩ S (plus m k)
        ≡⟨ plusSr m k ⟩ plus m (S k))
    n

Agda · Arith.agda

plus : ℕ → ℕ → ℕ
plus zero    m = m
plus (suc n) m = suc (plus n m)

plusZr : ∀ n → plus n zero ≡ n
plusZr zero    = refl
plusZr (suc n) = cong suc (plusZr n)

plusComm : ∀ n m → plus n m ≡ plus m n
plusComm zero    m = sym (plusZr m)
plusComm (suc k) m = begin
    plus (suc k) m   ≡⟨⟩
    suc (plus k m)   ≡⟨ cong suc (plusComm k m) ⟩
    suc (plus m k)   ≡⟨ sym (plusSr m k) ⟩
    plus m (suc k)   ∎
gainedThe induction hypothesis is a fact, not a value: ≡⟨ ih ⟩ needs no cong. Small here; it compounds a hundred times over in any real development.

Part 1 · vocabulary

The licence: what a proof may use

citationmeaning
x.eqthe proof may unfold definition x (compute with it)
l.rwuse lemma l as a left-to-right rewrite rule, at any subterm
luse lemma l by matching the whole goal — how commutativity is used; as a rule it would loop
hyp.rwuse the hypotheses in context (ih) as rewrite rules
pi.etacompare functions under the binder (η)
X.unfoldsee through a data type's name (V a n, Bag a) — needed for implicit arguments

Same theorem, rewriting style: using (plusZ.rw, plusS.rw, plusZr.rw, plusSr.rw) ≔ λn. λm. ℕ-elim ⋆ (k ih. ⋆) n

The hint usually names the citation. Fill holes first, cite last: goals print under the licence, so plus.eq makes plus display as its eliminator.

Part 2 · correct by construction

Reverse, with the lengths in the types

Nova · Vect.nova

def vrevAcc : {a : 𝕌} {n : ℕ} → V a n → {m : ℕ} → V a m → V a (plus n m)
  using (V.unfold, plusZ.rw, plusS.rw, plusSr.rw) ≔
  λa. λn. λv. VElim a (λk. λu. (m : ℕ) → V a m → V a (plus k m))
    (λm. λacc. acc)
    (λk. λx. λxs. λih. λm. λacc. ih (S m) (vcons a m x acc))
    n v

def vreverse : {a : 𝕌} {n : ℕ} → V a n → V a n
  using (V.unfold, plusZr.rw) ≔ λa. λn. λv. vrevAcc v (vnil a)

-- what the save before the citations said:
--   V a m              ≐ V a (plus Z m)      type
--   V a (plus k (S m)) ≐ V a (plus (S k) m)  type
--   V a (plus n Z)     ≐ V a n               type

Agda · Vect.agda

rev-acc : ∀ {A n m} → Vec A n → Vec A m → Vec A (n + m)
rev-acc []       acc = acc
rev-acc {A} {suc n} {m} (x ∷ xs) acc =
  subst (Vec A) (+-suc n m) (rev-acc xs (x ∷ acc))

reverse : ∀ {A n} → Vec A n → Vec A n
reverse {A} {n} xs = subst (Vec A) (+-identityʳ n) (rev-acc xs [])

-- n + suc m is not suc (n + m) by computation,
-- so the cons case does not type check without
-- the cast — a coercion INSIDE the program.
-- head (reverse v) is now stuck on subst for
-- a variable n; every proof pushes through it.
gainedThe program is the Haskell program. The three arithmetic facts are obligations about it, discharged once at the definition, and vreverse v123 ≡ v321 then holds by computation.

Part 2 · the statement Agda cannot write

vappend v vnil ≡ v

Nova · Vect.nova

def vappendNil : {a : 𝕌} {n : ℕ} (v : V a n)
  → vappend {a} {n} {Z} v (vnil a) ≡ v ∈ V a n
  using (hyp.rw, V.eq, V.unfold, VElim.eq, vnil.eq, vcons.eq,
         vappend.eq, plusZr.rw, plusZ.rw, plusS.rw) ≔
  λa. λn. λv. VElimP a
    (λk. λu. vappend {a} {k} {Z} u (vnil a) ≡ u ∈ V a k)
    ⋆ (λk. λx. λxs. λih. ⋆) n v

-- the statement alone, before any proof, reports:
--   V a (plus n Z) ≐ V a n   type
--   hint: closes with plusZr

Agda · Vect.agda

-- xs ++ [] : Vec A (n + 0)   but   xs : Vec A n
-- _≡_ needs both sides at ONE type. Either:

subst (Vec A) (+-identityʳ n) (xs ++ []) ≡ xs

-- or heterogeneous equality:
++-[] : ∀ {A n} (xs : Vec A n) → xs ++ [] ≅ xs
++-[] []       = H.refl
++-[] {A} {suc n} (x ∷ xs) =
  H.icong (Vec A) (x ∷_) (+-identityʳ n) (++-[] xs)

-- and then a library of subst-/≅-lemmas to use it.
gainedThe left side has type V a (plus n Z), the right V a n; Nova asks for plus n Z ≐ n, once, and forgets it ever came up. The proof is two ⋆s at a propositional motive — no coherence arguments, because equality proofs are unique.

Part 3 · extensional equality, concretely

The J-toolkit is one line each

Nova · Equality.nova

def sym   : {A : 𝕌} {a b : A} → (a ≡ b) → b ≡ a ≔ λA. λa. λb. λh. ⋆
def trans : {A : 𝕌} {a b c : A} → (a ≡ b) → (b ≡ c) → a ≡ c
  using (hyp.rw) ≔ λA. λa. λb. λc. λab. λbc. ⋆
def cong  : {A B : 𝕌} (f : A → B) {a b : A} → (a ≡ b) → f a ≡ f b
  ≔ λA. λB. λf. λa. λb. λh. ⋆

-- transport is the identity function
def subst : {A : 𝕌} (P : A → 𝕌) {a b : A} → (a ≡ b) → P a → P b
  ≔ λA. λP. λa. λb. λh. λp. p

-- uniqueness of equality proofs
def uip : {A : 𝕌} {a b : A} (p q : a ≡ b) → p ≡ q ≔ λA. λa. λb. λp. λq. ⋆

-- function extensionality is a THEOREM
def funext : {A B : 𝕌} {f g : A → B} → ((x : A) → f x ≡ g x) → f ≡ g
  using (pi.eta) ≔ λA. λB. λf. λg. λh. ⋆

Agda · Equality.agda

sym' refl = refl
trans' refl refl = refl
cong' f refl = refl

-- a real function: a NEW value at a new type,
-- with its own genre of lemmas (subst-subst, …)
subst' P refl p = p

-- needs K; false in cubical; not by matching
-- under --without-K even for ℕ
uip-ℕ refl refl = refl

-- not provable. Postulate (blocks computation)
-- or switch to --cubical (paths, not ≡)
postulate
  funext : (∀ x → f x ≡ g x) → f ≡ g
gainedReflection makes a and b the same term, so every combinator is ⋆ and P a is P b. Two things J cannot give — funext and UIP — are theorems.

Part 3 · for engineers

Program equivalence is equality

Nova · Equality.nova

def double1 : ℕ → ℕ ≔ λn. plus n n
def double2 : ℕ → ℕ ≔ λn. times 2 n

def double2Unfold : (n : ℕ) → double2 n ≡ plus n n
  using (double2.eq, times.eq, plusZr) ≔ λn. ⋆

-- equal AS FUNCTIONS: anything proved about one
-- transfers to the other by rewriting
def doublesAgree : double1 ≡ double2
  using (double1.eq, double2Unfold, pi.eta) ≔ ⋆

-- a vector whose length we LEARNED is 3 is a V ℕ 3
def learnedLength : {n : ℕ} (v : V ℕ n) (h : n ≡ 3) → V ℕ 3
  ≔ λn. λv. λh. v

Agda · Equality.agda

doublesAgree : double1 ≡ double2
doublesAgree = funext λ n → {! … !}   -- the postulate

-- pointwise agreement is all you get without it;
-- and a lemma about double1 does not rewrite to
-- one about double2 unless stated pointwise too

learnedLength : ∀ {n} → Vec ℕ n → n ≡ 3 → Vec ℕ 3
learnedLength v h = subst (Vec ℕ) h v
gainedRefactoring with a proof: two implementations, one equation, and the equation is usable everywhere an equation is. The learned fact about n retypes v with no cast.

Part 4 · quotients

A reducer that must not care about order

Nova · Bag.nova

data [a : 𝕌] ( Bag : U
     ; nil : El Bag
     ; ins : a → El Bag → El Bag
     ; swp : (x : a) (y : a) (m : El Bag)
             → ins x (ins y m) ≡ ins y (ins x m) ∈ El Bag )

-- a fold takes nil, ins, and a PROOF that ins commutes
def sum : Bag ℕ → ℕ using (Bag.unfold) ≔
  λm. BagElim ℕ (λw. ℕ) Z (λx. λr. λih. plus x ih)
    (λx. λy. λr. λih. plusSwap x y ih) m

-- (x y : ℕ) (ih : ℕ) ⊢ ?sumOk :
--   plus x (plus y ih) ≡ plus y (plus x ih)

Agda · Bag.agda (setoid)

data _≈_ : List A → List A → Set where
  ≈-refl ≈-sym ≈-trans ≈-cons ≈-swap : …

sum-resp : ∀ {xs ys} → xs ≈ ys → sum xs ≡ sum ys
sum-resp ≈-refl        = refl
sum-resp (≈-sym p)     = sym (sum-resp p)
sum-resp (≈-trans p q) = trans (sum-resp p) (sum-resp q)
sum-resp (≈-cons p)    = cong (_ +_) (sum-resp p)
sum-resp (≈-swap {x} {y} {xs}) = begin … ∎   -- the exchange law

-- once per function, forever. And this type checks:
first : List ℕ → ℕ
first (x ∷ _) = x     -- nobody is forced to try first-resp

-- --cubical: sum (swp x y m i) = exchange … i  (a path),
-- plus a trunc constructor with a clause in every function
gainedThe type checker derives "your reducer must commute" from the data type's equation, and refuses the reducer that doesn't. Map-reduce, CRDT merges, event-sourced aggregates: arrival-order independence as a type.

Part 4 · reasoning on the quotient

Sum of a union, by induction over a quotient

Nova · Bag.nova

-- respecting the swap is free: the inputs are EQUAL
def sumSwap : (x y : ℕ) (m : Bag ℕ)
  → sum (ins ℕ x (ins ℕ y m)) ≡ sum (ins ℕ y (ins ℕ x m))
  using (swp, Bag.unfold, ins.eq) ≔ λx. λy. λm. ⋆

def sumUnion : (m n : Bag ℕ) → sum (union m n) ≡ plus (sum m) (sum n)
  using (hyp.rw) ≔
  λm. λn. BagElimP ℕ (λw. sum (union w n) ≡ plus (sum w) (sum n))
    (sum (union (nil ℕ) n)
      ≡⟨ unionNil n ⟩ sum n
      ≡⟨ plusZ (sum n) ⟩ plus Z (sum n)
      ≡⟨ sumNil ⟩ plus (sum (nil ℕ)) (sum n))
    (λx. λr. λih. sum (union (ins ℕ x r) n)
      ≡⟨ unionIns x r n ⟩ sum (ins ℕ x (union r n))
      ≡⟨ sumIns x (union r n) ⟩ plus x (sum (union r n))
      ≡⟨ ih ⟩ plus x (plus (sum r) (sum n))
      ≡⟨ plusAssoc x (sum r) (sum n) ⟩ plus (plus x (sum r)) (sum n)
      ≡⟨ sumIns x r ⟩ plus (sum (ins ℕ x r)) (sum n))
    m

What is different

  • BagElimP eliminates into a proposition: no coherence argument for swp, because two proofs of an equation are equal.
  • Each case is a pen-and-paper chain over the computation rules sumNil, sumIns, unionNil, unionIns — proved once, by ⋆.
  • The chain link ≡⟨ ih ⟩ rewrites under plus x _ with no cong.
  • Setoid Agda: the same induction, plus sum-resp and union-resp first, and the result is a ≡ between numbers only because the codomain happens to be ℕ.

Part 5 · infinite data

Equality of infinite behaviours

Nova · Stream.nova

def stream : 𝕌 → 𝕌 ≔ λa. ν (K a × 𝕏)
def map : {a b : 𝕌} → (a → b) → stream a → stream b
  using (stream.unfold) ≔
  λa. λb. λf. λs. corec (t : stream a. f (hd t), tl t) s

def mapId : {a : 𝕌} (s : stream a) → map (id {a}) s ≡ s
  using (map.eq, hd.eq, tl.eq, id.eq, stream.unfold, hyp.rw) ≔
  λa. λs. coind
    (u v. ∥(w : stream a) × (u ≡ map (id {a}) w ∈ stream a)
                          × (v ≡ w ∈ stream a)∥)
    (⋆ (s, ⋆, ⋆))
    (u v h. squash-elim h (w. ⋆ (⋆, ⋆ (tl (w .π₁), ⋆, ⋆))))

-- and it rewrites, under map, under anything:
def evensFused : (s : stream ℕ)
  → map suc (map dbl s) ≡ map (suc ∘ dbl) s using (mapFuse) ≔ λs. ⋆

Agda · Stream.agda

record Stream (A : Set) : Set where
  coinductive
  field hd : A ; tl : Stream A

-- map id s ≡ s is NOT provable: ≡ sees syntax.
-- So: a second equality, by hand
record _≈_ (s t : Stream A) : Set where
  coinductive
  field hd-≈ : hd s ≡ hd t ; tl-≈ : tl s ≈ tl t

map-id : ∀ s → map (λ x → x) s ≈ s
hd-≈ (map-id s) = refl
tl-≈ (map-id s) = map-id (tl s)

-- ≈ does not rewrite and does not substitute,
-- so every function gets its own lemma:
map-cong : s ≈ t → map f s ≈ map f t
…
gainedBisimilarity is equality: coind takes an invariant and its one-step closure and hands back ≡. No second relation, no congruence lemma per function.

Part 6 · the price

What it costs, honestly

  • Undecidable conversion. That is why obligations and using exist. You will cite things. The hint usually says what; occasionally it suggests an unfolding that is worse than the lemma.
  • No metavariables, no unification. Binders are named, motives are written or recovered from the goal, implicits are recovered by first-order matching — sometimes you write {a} {n} {Z}.
  • No tactics. A proof is a term: eliminators, chains, ⋆. What the kernel replays is what you see.
  • Young. One-person project. The corpus — ℕ, ℤ, ℚ, Bishop's ℝ, groups, rings, fields, codata — is what has been built with it so far.
