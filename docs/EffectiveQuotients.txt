////////// EffectiveQuotients.txt — are Nova's quotients effective? //////////

////////// Purpose //////////

A RESEARCH NOTE, not a spec: it records one question, the answer, and
the changes the answer implies. What is normative lives in
docs/NovaFoundation.txt, docs/NovaKernel.txt and
docs/NovaElaboration.txt; §7 lists what this note put there.

STATUS. Answered, and acted on. §2 and §3 are the answer; §4 and §5 are
the implementation as measured BEFORE the fix, kept because they locate
the two gaps precisely; §6's P1 and P2 are now IMPLEMENTED (kernel:
one final; elaborator: two ⋆-witness routes) and the theorem of §3 is
proved in the library — src/nova/quotEffective.nova, Accepted. §9
records the outcome.

The question: el-quot-eq turns a relation witness into a class
equation,

    Γ ⊦ r : Prf R[id, a, b]  ⟹  Γ ⊦ class a ≐ class b : A / R

— is the converse available? A quotient is EFFECTIVE when it is: when
equal classes force the relation back out. Effectivity is what makes a
quotient a quotient rather than a lossy coarsening: without it, the
carrier's identifications are unknowable from inside, ⊎-style
no-confusion arguments have no analogue at (/), and every proof about
a quotient must be routed through a chosen representative.

Answer, in three parts:

  1. NAIVE effectivity — the converse of el-quot-eq, pointwise in R —
     is FALSE, and adding it as a rule would make the theory
     inconsistent (§2). This is not a gap; it is forced by ty-quot
     taking an ARBITRARY Ω-valued relation while ≐ is an equivalence.
  2. The TRUE characterization is closure-effectivity: quotient
     equality is exactly the equivalence closure r⁺ (§3), which is
     already definable in Nova (prop.nova's rClosure — impredicative
     intersection, no inductive machinery). Both directions are
     Foundation-derivable. For r proven an equivalence, effectivity on
     the nose follows as a corollary.
  3. In the IMPLEMENTATION, one direction works today; the other is
     blocked, and the block is two localized elaborator gaps, NOT a
     theory problem (§4, §5). Both are Ω-side: an Ω-equation and an
     Ω-valued quotient witness each have a faithful route the kernel
     replays but the surface cannot write. §6 proposes the fixes; the
     larger one costs one kernel constructor, the other costs nothing
     trusted at all.

Every claim below marked (measured) was checked against the
implementation at this commit; the files are listed in §8.

////////// 1. What effectivity would mean //////////

The rule one would like, stated in Foundation's style:

    Γ ▷ A ▷ A[↑] ⊦ R : Ω
    Γ ⊦ class a ≐ class b : A / R
    ------------------------------- (el-quot-eff — REFUTED, see §2)
    Γ ⊦ ⋆ : Prf R[id, a, b]

Foundation's Ω block already claims a version of this (Consequences
for quotients, item 2): "for R : Ω over Γ ▷ A ▷ A[↑], AN EQUIVALENCE
AT SQUASH LEVEL, class a ≐ class b : A / R implies Prf R[id, a, b]
inhabited". The qualifier is load-bearing, and §2 shows exactly how
much it is carrying. The same note's closing sentence — "combined with
r⁺ above this characterizes quotient equality for ARBITRARY relations"
— is the true statement; §3 makes it precise and, in one respect,
sharper than the note's own sketch.

////////// 2. Naive effectivity is refuted //////////

ty-quot imposes NO condition on R: any Ω-valued relation over
Γ ▷ A ▷ A[↑] forms A / R. Meanwhile ≐ is an equivalence at every one
of the seven judgement classes (Foundation, EQUIVALENCE RULES:
refl/sym/trans, adopted once and not repeated per class). So class
equality is closed under symmetry and transitivity whatever R is,
while R itself need not be either. Quotient equality is therefore at
least the equivalence closure of R together with A's own equality, and
el-quot-eq cannot be reversible pointwise.

This is not an abstract worry — the implementation proves the
witnessing equations (measured, E6):

    def SG : 𝕌 ≔ ℕ / (n m. (S n ≡ m ∈ ℕ))          -- the successor graph
    def hop1      : class Z ≡ class (S Z) ∈ El SG      ≔ ⋆
    def hop2      : class Z ≡ class (S (S Z)) ∈ El SG  ≔ ⋆
    def backwards : class (S Z) ≡ class Z ∈ El SG      ≔ ⋆

All three are Accepted. Now apply el-quot-eff to hop2: its relation
instance at (Z, S (S Z)) is (S Z ≡ S (S Z) ∈ ℕ), so we would get
⋆ : Prf (S Z ≡ S (S Z) ∈ ℕ); el-reflect gives S Z ≐ S (S Z) : ℕ; the
kernel's suc selector (§5 of NovaKernel.txt) gives Z ≐ S Z : ℕ; and
eqNat.nova's zNotS turns that into an inhabitant of 𝟘. The theory is
inconsistent. backwards refutes it just as fast, one hop earlier.

CONCLUSION: el-quot-eff must not be added — not to Foundation, and in
particular not as a kernel selector, where it would be an
inconsistency in the trusted layer. Any proposal that hands the user
"the relation back" unconditionally is this rule in disguise.

SEMANTICS agrees, and pins the exact failure. A type denotes a
structural code together with a proof-irrelevant EQUIVALENCE relation
on the code's decoding (Foundation, preface); the quotient clause
keeps ⟦El A⟧'s carrier and coarsens its relation by the truth of R at
each pair. A coarsening must remain an equivalence, so what ⟦El (A/R)⟧
actually carries is the equivalence closure of ~_A ∪ R. Foundation's
phrasing of that clause ("coarsens its relation by the truth of R at
each pair") is exact only when R is already an equivalence containing
~_A; otherwise read it as the closure (§7 asks for the clarification).

One consequence is worth recording because it is the first thing one
worries about. If ⟦El (A/R)⟧ depends only on the closure, do A / R and
A / R⁺ become the same type, and does ty-quot-inj then prove R ↔ R⁺
(which is false)? No: type equality is equality of CODES, and the
quotient code carries its relation, compared at Ω by inhabitation. R
and R⁺ are not pointwise equi-inhabited, so the codes differ, the
types differ, and ty-quot-inj is untouched. The price is that A / R
and A / R⁺ are distinct types with identical element relations — so
the characterization in §3 must be proved INSIDE A / R, not by
transporting along a type equation that does not exist.

////////// 3. The true characterization: closure-effectivity //////////

Write r⁺ for prop.nova's rClosure — the intersection of every
equivalence relation containing r, a single impredicative Π over Ω,
with rClosureContains / rClosureRefl / rClosureSymm / rClosureTrans /
rClosureLeast already proved in the corpus.

  THEOREM (closure-effectivity). For A : 𝕌 and r : El A → El A → Ω,

      Prf (class a ≡ class b ∈ El (A / r))   ⟺   Prf (r⁺ a b)

  ⟸  Q x y ≔ (class x ≡ class y ∈ El (A / r)) is an equivalence
     relation (Foundation's EQUIVALENCE RULES, read through
     el-reflect) containing r (el-quot-eq). Leastness of r⁺
     (rClosureLeast) gives r⁺ ⊆ Q.

  ⟹  quot-elim at the CONSTANT MOTIVE Ω with f ≔ (x. r⁺ a x):

       * well-definedness: for x, y with Prf (r x y),
         r⁺ a x ≐ r⁺ a y : Ω by code-prop-eq, both implications from
         rClosureContains + rClosureTrans + rClosureSymm;
       * el-quot-beta: the descended P satisfies P (class x) ≜ r⁺ a x;
       * congruence on the class equation: P (class a) ≐ P (class b),
         i.e. r⁺ a a ≐ r⁺ a b : Ω;
       * ty-prf-cong + el-ty-coe move rClosureRefl's ⋆ across it.

  COROLLARY (effectivity on the nose). If r is proven reflexive,
  symmetric and transitive then r⁺ ⊆ r by leastness, so
  Prf (class a ≡ class b ∈ El (A / r)) ⟺ Prf (r a b).

Two notes on the ⟹ direction. First, it needs NO hypothesis on r: the
motive is the closure, not r, so well-definedness is discharged by
r⁺'s own equivalence properties. That is sharper than Foundation's
sketch, which descends R itself and therefore needs R's symmetry and
transitivity; the r⁺ motive makes the "combined with r⁺" remark a
single derivation rather than a two-step detour. Second, it stays
inside A / r throughout — no map to A / r⁺ is built, which matters
because (§2) those are distinct types.

In surface syntax the whole ⟹ direction is four lines:

    def rel : (A : 𝕌) (r : El A → El A → Ω) (a : El A) → El (A / (u v. r u v)) → Ω ≔
      λA. λr. λa. λq. quot-elim (_. Ω) (x. rClosure A r a x) q

    def effective : (A : 𝕌) (r : El A → El A → Ω) (a : El A) (b : El A) →
      Prf (class a ≡ class b ∈ El (A / (u v. r u v))) → Prf (rClosure A r a b) ≔
      λA. λr. λa. λb. λh. transportP _ (rel A r a) _ _ h (rClosureRefl A r a)

////////// 4. What the implementation did before the fix (measured) //////////

  ⟸ direction, concrete relation: WORKS. For Int = (ℕ ⨯ ℕ) / IntR the
    full leastness argument elaborates and is Accepted (E8) — the four
    premises (containment by el-quot-eq, reflexivity, transitivity,
    symmetry) are each one ⋆ or one equality combinator.

  ⟹ direction, architecture: WORKS. At a relation whose
    well-definedness happens to be automatic, the entire derivation of
    §3 — quot-elim at motive Ω, β, transport along the class equation
    — elaborates and is Accepted (E10). The Ω motive is fine in the
    kernel; the transport and the β step are fine.

  ⟹ direction, in general: BLOCKED, by exactly one obligation. For the
    generic statement (E4) and for Int (E5) the ONLY open obligations
    are the quot-elim well-definedness at Ω:

      rClosure A r a x ≐ rClosure A r a x' : Ω     (E4)
      IntR a x ≐ IntR a x' : Ω                     (E5)

    Everything else in the derivation — including E5's reflexivity ⋆
    at Prf (IntR a a), which needs commutativity — goes through. Int's
    effectivity is one propositional extensionality away.

  ⟸ direction, generic in r: BLOCKED. With r a variable, el-quot-eq
    itself is unavailable: Prf (r x y) in hand does not yield
    class x ≐ class y (E1). Same for any structured concrete relation
    — a conjunction (E3) or a disjunction (E9) fails the same way.

  PRESENT WORKAROUND in the corpus. A quotient equipped with a
  chosen-representative function gets effectivity today by descending
  an EQUALITY-prop motive instead of an Ω one: equality props are
  proof-irrelevant, so well-definedness is free. That is exactly what
  eqInt.nova does (intNormalizeId, eqISound/eqIComplete), and its
  header comment already diagnoses why the general route is closed. It
  requires a normalization function, so it does not generalize.

  THE QIIT PRESENTATION does not help, and the reason is structural.
  qiitQuot.nova presents the same type with a PROOF-CARRYING equation
  constructor, qeq : (x y) → Prf (r x y) → cls x ≡ cls y ∈ El Q, and
  that constructor works at an ABSTRACT relation (E13a, Accepted) —
  precisely what the primitive (/) cannot do. But QIIT eliminator
  motives are displayed algebras over U, i.e. TERMS at 𝕌, and there is
  no code for Ω in 𝕌 (the load-bearing prohibition of the Ω block): an
  Ω motive is not even parseable there (E15, against the 𝕌-code
  control E14). So the QIIT
  presentation has the introduction Nova's primitive quotient lacks,
  and can never have the elimination effectivity needs. Neither
  presentation is complete alone.

////////// 5. The two gaps, located //////////

GAP A — code-prop-eq has no user-supplied route (blocks ⟹).

  The kernel's propext final is fully general: FPropExt carries two
  proof terms and replays them as hypothetical typings
  (Kernel.idr:1548; NovaKernel.txt §7, "propext ..."). The ELABORATOR
  synthesizes those two terms and can only do so in two shapes —
  a 𝟙-shaped squash, or an equality prop closed by a nested discharge
  (Elaboration.idr, mkImpl, ~:1425). Anything else returns Nothing,
  the discharge falls through to class-/congruence-decomposition, and
  the user is handed obligations STRICTLY STRONGER than the goal:
  x ≐ x' : El A in E4, x .π₁ ≐ x' .π₁ in E5. There is no surface
  syntax for supplying the implications, so a propext that needs real
  content (E5's needs cancellation on ℕ; no synthesis will ever find
  it) is unreachable.

  Note the shape of the failure: the elaboration spec's own table
  (NovaElaboration.txt, ↓ finals) already calls propext "the faithful
  route at Ω" and says the two implications come "each with its
  witness SYNTHESIZED under the hypothesis". Synthesis is the whole
  policy; there is no fallback.

GAP B — el-quot-eq is shape-restricted (blocks ⟸ generically).

  Both layers re-derive the witness from the relation's SHAPE instead
  of taking a proof: the elaborator fires only at ∥𝟙∥ or an equality
  prop (Elaboration.idr:1411-1416), and the kernel's FWitness accepts
  only those two, rejecting anything else as "witness final at a
  non-evident relation" (Kernel.idr:1514-1528). So quotients by ∧, ∨,
  ⊃, ∀-shaped or abstract relations cannot introduce a single class
  equation. Casualties:

    * the generic ⟸ direction (E1, E2);
    * quotients by r⁺ itself, whose relation is a Π-squash — so the
      A / r → A / r⁺ mediating map cannot be built either;
    * Foundation's own derivation of prf-codes (Ω block: "effectivity
      along (x ≡ y ∈ ℕ) ∨ r"), which needs a ∨-shaped relation (E9).
      That claimed derivation is currently not executable.

  `⋆ e` does not help: at a class-equation goal it is read as
  squash-intro, infers Prf ∥Prf (r x y)∥ = Prf (r x y), and then
  demands a propext bridge between the relation and the class equation
  — which is effectivity itself, i.e. circular (E2, E9).

MINOR GAP C — a squashed conjunction in the context is not unpacked
  for rewriting (measured, E12): h : Prf ∥Prf (x ≡ x' ∈ ℕ) ⨯ …∥ does
  not license x ≐ x'. This is as specified (the engine's projection-
  chain fact covers a BARE Σ-tree of Prf-equalities, not a squashed
  one — unpacking needs squash-elim, a proof term, not a candidate),
  and Gap A's fix subsumes it: once implications can be written by
  hand, the user squash-elims the hypothesis there.

  Also measured (E11 vs E12), and load-bearing for §6: a prepended
  lemma whose statement is the Ω-equation DOES discharge a quot-elim
  well-definedness obligation, with its Prf argument filled from the
  context hypothesis. So Gap A needs no new plumbing at the quot-elim
  site — only a way to prove the lemma.

////////// 6. Ways to make quotients effective //////////

P1 (RECOMMENDED, no trust growth) — proof-carrying propext.

  Let the surface supply the two implications of code-prop-eq. In the
  existing idiom — e-star's note already says a proposition that is
  not evident in one of the two automatic shapes is written `⋆ e` with
  the witness supplied directly — the natural spelling reuses that
  form at an Ω-equation goal:

      Γ ⊦ f ⇐ Prf p → Prf q      Γ ⊦ g ⇐ Prf q → Prf p
      ------------------------------------------------ (e-star-propext)
      Γ ⊦ ⋆ (f , g) ⇐ Prf (p ≡ q ∈ Ω)

  Elaboration: at checkStarWitAt, when the exposed prop is
  EqTy p q Ty.PropTy, check the two components and emit FPropExt. No
  new parser rule: `⋆ (f , g)` already parses.

  AS BUILT, one correction to the above. The plan was to keep the
  kernel untouched by handing FPropExt the applied forms f[↑] ☐₀ and
  g[↑] ☐₀ — its existing contract is the two HYPOTHETICAL proofs. That
  cannot be done from the elaborator: a surface variable carries the
  de Bruijn index the parser resolved (SVar name i), so a term checked
  in Γ cannot be re-checked under an extra binder, and weakening it
  would mean weakening its skeleton's payloads too. FPropExt's contract
  therefore now carries the implications AS FUNCTIONS over Γ, which the
  kernel applies itself — the same rule (Π intro/elim), one line of
  replay changed, and the automatic synthesis wraps its old output in a
  λ. No new constructor, and the trusted surface is unchanged in size.

  Delivers: every Ω-valued well-definedness obligation becomes
  provable by hand, hence (with §5's lemma-discharge fact) the ⟹
  direction of the theorem — generically (E4) and for Int (E5) — plus
  Gap C's conjunction cases. This is the fix that makes quotients
  effective.

P2 (RECOMMENDED, one kernel constructor) — proof-carrying quotient
  witness. Give the primitive quotient the discipline the QIIT
  presentation already has (§4): let the class equation take its
  witness instead of pattern-matching the relation's shape.

      Γ ⊦ w ⇐ Prf R[id, a, b]
      -------------------------------------------- (e-star-quot-wit)
      Γ ⊦ ⋆ w ⇐ Prf (class a ≡ class b ∈ A / R)

  Kernel: FWitness gains a proof-license variant, replayed by kCheckE
  at Prf (rel[a, b]) — literally el-quot-eq's premise, so the trusted
  surface grows by one already-Foundation-licensed rule and by the
  same amount FPropExt already costs. Elaboration: one case in
  checkStarWitAt, where `⋆ e` currently falls through to squash-intro.

  Delivers: class introduction at arbitrary Ω relations — the generic
  ⟸ direction, quotients by r⁺, the A / r → A / r⁺ map, and
  Foundation's prf-code derivation.

  P1 and P2 are independent, and P1 alone already makes concrete
  quotients effective. Together they give the §3 theorem in full,
  entirely in the library: prop.nova / quotient.nova, no theory change.

P3 (OPTIONAL, after P1/P2) — cheap automation on top: when the
  required implication is inhabited by a context hypothesis, or by a
  scoped lemma applied to hypotheses, synthesize it. Strictly a
  convenience, incomplete, and library-coupled if it learns about ↔
  (which is a prop.nova definition, not kernel vocabulary). Not a
  substitute for P1: E5's implication is a cancellation lemma no
  search will find.

P4 (REJECTED) — a primitive effectivity rule or kernel selector.
  Unsound in the naive form (§2). A form guarded by three equivalence
  proofs IS sound, but it is a library corollary of P1+P2 (§3
  corollary), so it would enlarge the trusted layer for zero
  expressive gain.

P5 (REJECTED, recorded for completeness) — the alternative DESIGN:
  restrict ty-quot / code-quot to relations shipped with reflexivity,
  symmetry and transitivity proofs. Then effectivity holds on the nose
  and el-quot-eff becomes sound as a primitive. Costs: every quotient
  carries three proofs; A / r for a raw r must be spelled A / r⁺, so
  P2 is still needed to introduce its classes; Foundation loses the
  "arbitrary Ω-valued relation" simplicity, and ty-quot's premises
  stop being decidable-by-shape. It buys nothing P1+P2 do not buy in
  the library, and it changes the theory rather than the elaborator.

////////// 9. Outcome //////////

Implemented, and the theorem proved.

  KERNEL (src/idris/Nova/Kernel.idr)
    * witnessPrf / FWitnessPrf: a new final — el-quot-eq's premise,
      presented. Replays by checking the supplied witness at
      Prf r[id, a, b]. One already-licensed rule; nothing else in the
      trusted layer moved.
    * propext / FPropExt: same rule, new contract — the implications
      arrive as FUNCTIONS over Γ and the kernel applies them, because
      the elaborator cannot hand over a term to be checked under a
      binder it did not itself introduce (§6, AS BUILT).

  ELABORATOR (src/idris/Nova/Elaboration.idr)
    * two ⋆-witness routes in checkStarWitAt, dispatched on the GOAL:
      `⋆ (f , g)` at an Ω-equation (e-star-propext), `⋆ e` at a class
      equation over a quotient (e-star-quot-wit). Any other goal keeps
      the previous readings — squash-intro, or a license for the very
      equation being proved.
    * the automatic propext synthesis (mkImpl) now returns λ-wrapped
      implications, matching the new contract. Unchanged in reach: the
      evident shapes are still the only ones it finds by itself, which
      is the point — content is supplied, not searched.

  LIBRARY
    * prop.nova: propExt (code-prop-eq at arbitrary propositions) and
      propExtOfIff (the same against ↔).
    * quotEffective.nova — the theorem: classEqOfRel (el-quot-eq at an
      arbitrary, possibly variable relation), classEqOfClosure (⟸),
      clsRelWd + clsRel (the closure descended to the quotient),
      effective (⟹ — EFFECTIVITY), classEqIff (the characterization),
      effectiveAtEquiv (the on-the-nose corollary), an instance of it at
      ℕ, and the successor-graph refutation as standing evidence.
      Accepted, zero obligations.
    * intEffective.nova — Int ON THE NOSE: equal classes give IntR
      back. effectiveAtEquiv carries the quotient reasoning and asks
      only that IntR be an equivalence, which is arithmetic:
      reflexivity and symmetry are one ⋆ each (commutativity), and
      transitivity is cancelTrans — the two hypotheses walked across a

    * nat.nova gained the arithmetic that needed: sucInj (the kernel's

      whole-equation matching against plusAssoc/plusComm/swapLeft).

  REMAINING: P3's convenience search, and the two minor findings above.

  One observation worth keeping, from proving Int. The discharge engine
  chains a hypothesis into a rearrangement only when the whole equation
  matches a candidate; it will not combine TWO hypotheses across a
  permutation (⋆ at cancelStep's goal decomposes componentwise and
  fails, even with plusAssoc/plusComm/swapLeft in scope). Hence the
  explicit trans-chain there. The commutative-monoid solver under
  src/idris/Solver is not wired into the engine — if it were, that
  chain and several of nat.nova's inductive ⋆-proofs would collapse to
  one step. A separate piece of work, and a well-defined one.
