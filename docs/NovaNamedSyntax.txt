// NovaNamedSyntax.txt — named surface syntax for .rules/.target files
//
// This is NOT a new core calculus. Ty/Elem, the checker's `step` function,
// and every reduction/substitution rule (NovaSyntax.txt, NovaFoundation.txt)
// are completely unchanged and stay 100% de Bruijn-indexed (☐ₙ) internally.
// This file specifies a *surface* grammar only — the concrete syntax an
// AI/human actually writes and reads in .rules/.target files — which is
// parsed to and pretty-printed from the exact same core AST NovaSyntax.txt
// describes. Translation is a pure front-end concern, entirely outside the
// checker.
//
// Two different things need naming, for two different reasons:
//
//   1. `ctx-ext` / `el-var` — the *incremental* case. While a `.rules` file
//      is building up a context Γ step by step, the tool tracks a name
//      environment alongside it (one name per entry, same order/length as
//      Γ). `ctx-ext Γ ᐅ x:T` records the name; `el-var Γ ⊦ x` resolves it.
//      A name resolves to whichever index currently sits at that position
//      — innermost binder wins, ordinary lexical shadowing, no freshness
//      requirement — and every later fact stated against that same Γ
//      prints/parses using those names for free. Weakening is "free" too:
//      composing with `↑` never changes what a variable is called, only
//      which index it resolves to.
//
//   2. `→`, `⨯`, `/`, `λ`, `ℕ-elim`'s step branch, `quot-elim`'s motive —
//      the *wrapping* case. The moment one of these rules packages a fact
//      derived against an incrementally-named context into a single
//      compound value (a Pi type, a lambda, ...), that variable is popped
//      out of the tracked context into an anonymous internal binder slot.
//      That's recoverable *while a `.rules` file is mid-derivation* (the
//      tool still remembers the name from the `ctx-ext` that built the
//      wrapped context, and can auto-fill it into what it prints) — but a
//      compound value is routinely displayed or stored on its own, with no
//      accompanying `ctx-ext` trail at all: a `.target` line, a `sig`'s
//      printed type, a `dump`/`apply` echo. `el-wf ε ⊦ vappend[] : ℕ → 𝕌
//      → ℕ → El(vect n A) → ...` has to be self-describing — `ε` obviously
//      isn't where `n`/`A`/`m` got their names. So these constructs carry
//      their bound name(s) *inline*, in their own surface syntax, not only
//      via the context they happen to have been built against.
//
// In short: `ctx-ext`'s name is where a variable is *introduced*; a
// wrapping construct's inline name is where it's *recorded* once that
// variable stops being a tracked context entry and becomes a compiled-in
// binder. During interactive `apply`/`query` use, the tool can still
// auto-fill a wrapping construct's inline name from the immediately
// preceding `ctx-ext` (write `_` to mean "reuse whatever name is already
// there") so the AI never has to retype it — but the canonical, persisted,
// printed form always carries it explicitly, because it has to survive
// being read with no other context at all.
//
// x, y, z, n, m, k, ... range over surface identifiers (names): letters,
// digits, `'`, `_`, freely chosen, no uniqueness/freshness requirement
// (shadowing is legal and resolves to the innermost binder, same as any
// ordinary lexically-scoped language). `_` is the wildcard/anonymous name
// (bound but not meant to be referenced) and, in the constructs listed
// under (2), may be dropped entirely as sugar — see below. A signature
// reference is always written x[e˲] (bracketed) — never bare — so a bare
// identifier is unambiguously a local named variable, never a signature
// lookup; the two namespaces cannot collide syntactically.

// No id/↑/∘: every substitution actually needed is an explicit, flat
// extension list, exactly like t˲ below (this is also true of the
// indexed grammar — see NovaSyntax.txt). Id/Wk/Chain still exist on the
// core Sub type (used internally, e.g. for quotient-type formation's
// `A[↑]`) — they're just not surface-syntax-constructible here (no
// sub-id/sub-wk/sub-chn rule).
//
// The empty/terminal substitution is written as literally no text at all —
// `·` is NOT valid syntax in this position. A non-empty substitution is a
// bare comma-separated element list with no leading marker, e.g. `n, A, m`
// (not `·, n, A, m`). Same for t˲ below.
σ ::= (empty) | t{≥1} (, t{≥1})*                                            Ext (left-assoc)

T{4} ::= 𝟘 | 𝟙 | ℕ | 𝕌 | (T{≥0})
T{3} ::= T{≥3}[σ{≥0}]
T{2} ::= El t{≥4}
T{1} ::= (x:T{≥0}) → T{≥1} | (x:T{≥0}) ⨯ T{≥1} | T{≥2} / (x y. T{≥1})      (right-assoc)
T{0} ::= t{≥2} ≡ t{≥2} ∈ T{≥1}

// Sugar: `A → B` for `(_:A) → B`, `A ⨯ B` for `(_:A) ⨯ B`, `A / R` for
// `A / (_,_. R)` — i.e. the name(s) may be dropped whenever the codomain/
// relation doesn't reference them, exactly as `A → B` already reads today
// when nothing internally depends on the argument (e.g. `ℕ → ℕ → ℕ`).
// The named form's domain is a full, unrestricted T{≥0} — it's already
// delimited by the binder's own parens, so e.g. `(x:El A → 𝕌) → B` needs no
// further wrapping around the domain. Only the sugared, name-dropped form
// has no such delimiter, so *its* domain stays restricted to T{≥2} (hence
// `El A → 𝕌 → ℕ` unambiguously right-associates instead of grouping the
// first arrow into the domain of the second).

t˲ ::= (empty) | t{≥1} (, t{≥1})*

t{5} ::= x | () | Z | Refl | 𝟘 | 𝟙 | ℕ | x[t˲] | (t{≥0})
t{4} ::= t{≥4} [σ{≥0}]
t{3} ::= t{≥3} t{≥4} | t{≥3} .π₁ | t{≥3} .π₂                               (left-assoc)
t{2} ::= λx. t{≥3} | 𝟘-elim t{≥4} | S t{≥4} | ℕ-elim t{≥4} (n ih. t{≥4}) t{≥4} | class t{≥4} | quot-elim t{≥4} t{≥4}
t{1} ::= (x:t{≥0}) → t{≥1} | (x:t{≥0}) ⨯ t{≥1} | t{≥2} ≡ t{≥2} ∈ t{≥2}
t{0} ::= t{≥1} , t{≥0}                                                      SigmaIntro (right-assoc)

// Same sugar as above applies to λ (`λ. f` for `λ_. f` is not useful since
// λ always binds something f might use, but `_` is still legal to write
// when f happens not to reference it) and to `ℕ-elim`'s step branch
// (`n ih.` may each independently be `_` when `s` doesn't use them).
// `quot-elim f q` itself carries no name — unlike `ℕ-elim`, it has no
// slot in its own runtime term for a bound motive; naming happens only at
// `el-quot-elim`'s `motive` annotation below, the one place that binder is
// ever spelled out.

Γ ::= ε | Γ ᐅ x:T{≥0}                                                       (left-assoc)
Δ ::= ε | x:T{≥0} ◁ Δ                                                       (right-assoc)
ē ::= · | t{≥1} (, t{≥1})*

α{5} ::= ↓ | id | (α{≥0})
α{4} ::= α{≥4} [α{≥0}]
α{3} ::= α{≥3} α{≥4} | α{≥3} .π₁ | α{≥3} .π₂                               (left-assoc)
α{2} ::= λ α{≥4} | 𝟘-elim α{≥4} | S α{≥4} | El α{≥4} | ℕ-elim α{≥4} α{≥4} α{≥4} | quot-elim α{≥4} α{≥4}
α{1} ::= α{≥2} → α{≥1} | α{≥2} ⨯ α{≥1} | α{≥2} ᐅ α{≥1}                     (right-assoc)
       | α{≥2} ≡ α{≥2} ∈ α{≥2}
α{0} ::= α{≥1} , α{≥0} | α{≥1} ; α{≥0}                                       (right-assoc)

// α (compute rules) is unchanged and needs no names of its own: a compute
// path only ever navigates *inside* an already-named term/type that was
// built (and named) earlier — it never introduces a new binder.

// TypingRule — syntax of derivation steps in .rules files
// Same keyword, same arity, same premises as NovaSyntax.txt throughout.
// What changes is: (a) `ctx-ext`/`el-var` per the incremental case above,
// and (b) every rule whose conclusion *wraps* a fact into a Pi/Sigma/
// Quotient/λ/ℕ-elim/quot-elim value now shows that value using the named
// T{1}/t{2} forms above instead of the old bare `A → B`/`λ f`/etc. — the
// rule keyword and premises are identical, only the printed/written
// conclusion syntax carries names now.
R ::=

  // Context
  ctx-emp                                        (CtxWfEmpty)
  ctx-ext    Γ ᐅ x:T                             (CtxWfExt — NAMED: was `Γ ᐅ T`)
  ctx-refl   Γ                                   (CtxEqRefl)
  ctx-sym    Γ₁ ≐ Γ₀                             (CtxEqSym, conclusion: Γ₁ ≐ Γ₀)
  ctx-trans  Γ₀ ≐ Γ₂ via Γ₁                     (CtxEqTrans, conclusion: Γ₀ ≐ Γ₂)
  ctx-cmp    Γ via α                              (CtxWfCompute)

  // Substitution wf
  sub-term   Γ ⊦                                 (SubWfTerminal — nothing after ⊦, not `·`)
  sub-ext    Γ ⊦ σ, e to Δ ᐅ T

  // Substitution eq
  sub-refl   Γ ⊦ σ : Δ
  sub-sym    Γ ⊦ σ₁ ≐ σ₀ : Δ                   (conclusion: σ₁ ≐ σ₀)
  sub-trans  Γ ⊦ σ₀ ≐ σ₂ : Δ via σ₁            (conclusion: σ₀ ≐ σ₂)

  // Normal substitution wf
  sub-norm-term   Γ ⊦                            (SubNormWfTerminal — nothing after ⊦, not `·`)
  sub-norm-ext    Γ ⊦ e˲, t to Δ ᐅ T             (SubNormWfExt)

  // Normal substitution eq
  sub-norm-refl    Γ ⊦ e˲ : Δ
  sub-norm-sym     Γ ⊦ e˲₁ ≐ e˲₀ : Δ                 (conclusion: e˲₁ ≐ e˲₀)
  sub-norm-trans   Γ ⊦ e˲₀ ≐ e˲₂ : Δ via e˲₁         (conclusion: e˲₀ ≐ e˲₂)
  sub-norm-ext-eq  Γ ⊦ e˲₀, t₀ ≐ e˲₁, t₁ : Δ ᐅ T    (SubNormEqExt, ext-eq before ext — longer keyword first)

  // Type wf
  ty-zero    Γ ⊦ 𝟘
  ty-one     Γ ⊦ 𝟙
  ty-nat     Γ ⊦ ℕ
  ty-univ    Γ ⊦ 𝕌
  ty-pi      Γ ⊦ (x:A) → B                      (NAMED: was `A → B`; x may default to whatever name the ctx-ext for A's extension already used, or `_`)
  ty-sigma   Γ ⊦ (x:A) ⨯ B                      (NAMED: was `A ⨯ B`, same default as ty-pi)
  ty-eq-form Γ ⊦ l ≡ r ∈ A
  ty-el      Γ ⊦ El e
  ty-quotient Γ ⊦ A / (x y. R)                  (TyWfQuotient — NAMED: was `A / R`, x y name R's two arguments)
  ty-cmp     Γ via α ⊦ T via β                  (TyWfCompute)
  ty-wf-subst Γ₀ ⊦ σ to Γ₁ ⊦ A                  (TyWfSubst, conclusion: Γ₀ ⊦ A[σ])

  // Type eq
  ty-refl    Γ ⊦ T
  ty-sym     Γ ⊦ T₁ ≐ T₀                        (conclusion: T₁ ≐ T₀)
  ty-trans   Γ ⊦ T₀ ≐ T₂ via T₁                 (conclusion: T₀ ≐ T₂)
  ty-eq-cong Γ ⊦ (a₀ ≡ b₀ ∈ T₀) ≐ (a₁ ≡ b₁ ∈ T₁) (TyEqCongEqTy)
  ty-el-cong Γ ⊦ El t₀ ≐ El t₁                   (TyEqCongEl)
  ty-eq-subst Γ₀ ⊦ σ₀ ≐ σ₁ to Γ₁ ⊦ A₀ ≐ A₁        (TyEqSubst, conclusion: Γ₀ ⊦ A₀[σ₀] ≐ A₁[σ₁])

  // Element wf: intro / elim
  el-var      Γ ⊦ x                              (ElemWfVar — NAMED: was `Γ ⊦ ☐ₙ`; looks x's type up in Γ by name, no index/no A[↑]ⁿ⁺¹ bookkeeping to write)
  el-one      Γ ⊦ ()
  el-zero     Γ ⊦ Z
  el-suc      Γ ⊦ S t
  el-pi-i     Γ ⊦ λx. f : (x:A) → B             (NAMED: was `λ f : A → B`)
  el-pi-e     Γ ⊦ (f : A → B) e
  el-sigma-i  Γ ⊦ u, v : A ⨯ B
  el-sigma-e1 Γ ⊦ (e : A ⨯ B) .π₁
  el-sigma-e2 Γ ⊦ (e : A ⨯ B) .π₂
  el-zero-e   Γ ⊦ 𝟘-elim e : T
  el-nat-e    Γ ⊦ ℕ-elim z (n ih. s) t motive (n ih. A)  (NAMED: was `ℕ-elim z s t motive A`; A in Γᐅn:ℕ, not A[t] — see cheat sheet)
  el-class    Γ ⊦ class a : A / R                (ElemWfClass)
  el-quot-elim Γ ⊦ quot-elim f (q : A / R) motive (q'. B) (ElemWfQuotElim — NAMED: was `motive B`; B in Γᐅq':(A/R), not B[q])
  el-wf-subst Γ₀ ⊦ σ to Γ₁ ⊦ t : A              (ElemWfSubst, conclusion: Γ₀ ⊦ t[σ] : A[σ])
  el-reflect  Γ ⊦ t : (l ≡ r ∈ A) reflect       (ElemEqReflection)
  el-refl     Γ ⊦ Refl : t ∈ A                  (ElemWfRefl)
  el-ty-coe   Γ ⊦ t : T₀ ↝ T₁
  el-ctx-coe  Γ₀ ≐ Γ₁ ⊦ t : T

  // Element wf: universe codes
  el-zero-ty  Γ ⊦ 𝟘 : 𝕌
  el-one-ty   Γ ⊦ 𝟙 : 𝕌
  el-nat-ty   Γ ⊦ ℕ : 𝕌
  el-pi-ty    Γ ⊦ (x:A) → B : 𝕌                 (NAMED: was `A → B : 𝕌`)
  el-sigma-ty Γ ⊦ (x:A) ⨯ B : 𝕌                 (NAMED: was `A ⨯ B : 𝕌`)
  el-eq-ty    Γ ⊦ l ≡ r ∈ A : 𝕌
  el-cmp      Γ via α ⊦ t via β : T via γ       (ElemWfCompute)

  // Signature
  sig-var-eq Γ ⊦ x[e˲]                           (ElemEqSigVar — x here is a *signature* identifier, always bracketed, never a local name)
  sig-var    Γ ⊦ x[e˲]                           (ElemWfSigVar)
  sig        Γ ⊦ x ≔ t : T                      (SigExt)

  // Element equality
  el-ty-coe-eq Γ ⊦ t₀ ≐ t₁ : T₀ ↝ T₁           (ElemEqTyCoe)
  el-eq-refl   Γ ⊦ t : T                        (ElemEqRefl)
  el-eq-sym    Γ ⊦ t₁ ≐ t₀ : T                  (conclusion: t₁ ≐ t₀)
  el-eq-trans  Γ ⊦ t₀ ≐ t₂ : T via t₁           (conclusion: t₀ ≐ t₂)
  el-suc-cong  Γ ⊦ S t₀ ≐ S t₁                   (ElemEqCongSuc)
  el-app-cong  Γ ⊦ (f₀ ≐ f₁ : A → B) t₀ ≐ t₁     (ElemEqCongPiApp, conclusion: f₀ t₀ ≐ f₁ t₁ : B[t₁])
  el-class-cong Γ ⊦ class a₀ ≐ class a₁ : A / R  (ElemEqCongClass)
  el-quot-eq   Γ ⊦ class a ≐ class b : A / R via r (ElemEqQuotient, r : R[a, b])
  el-eq-subst  Γ₀ ⊦ σ₀ ≐ σ₁ to Γ₁ ⊦ t₀ ≐ t₁ : A   (ElemEqSubst, conclusion: Γ₀ ⊦ t₀[σ₀] ≐ t₁[σ₁] : A[σ₁])

  // Telescope equality
  tel-refl   Γ ⊦ Δ
  tel-sym    Γ ⊦ Δ₁ ≐ Δ₀
  tel-trans  Γ ⊦ Δ₀ ≐ Δ₂ via Δ₁

  // Spine equality
  sp-refl    Γ ⊦ s : Δ
  sp-sym     Γ ⊦ s₁ ≐ s₀ : Δ
  sp-trans   Γ ⊦ s₀ ≐ s₂ : Δ via s₁

// JudgementForm — syntax of target goals in .target files
// Each form starts with a unique keyword; no trailing disambiguators needed.
// These are exactly where self-containedness matters most — a `.target`
// file has no `ctx-ext` trail of its own at all, so any Pi/Sigma/Quotient/
// λ/ℕ-elim/quot-elim appearing in Γ/T/t here MUST use the named forms
// above; there is nothing to auto-fill from.
J ::=
  ctx-wf  Γ                           (JfCtxWf)
  ctx-eq  Γ ≐ Γ'                      (JfCtxEq)
  sub-wf  σ : Γ ⇒ Δ                   (JfSubWf)
  sub-eq  σ ≐ σ' : Γ ⇒ Δ              (JfSubEq)
  sub-norm-wf  e˲ : Γ ⇒ Δ norm        (JfSubNormWf)
  sub-norm-eq  e˲ ≐ e˲' : Γ ⇒ Δ norm  (JfSubNormEq)
  ty-wf   Γ ⊦ T                       (JfTyWf)
  ty-eq   Γ ⊦ T ≐ T'                  (JfTyEq)
  el-wf   Γ ⊦ t : T                   (JfElemWf)
  el-eq   Γ ⊦ t ≐ t' : T              (JfElemEq)
  tel-wf  Γ ⊦ Δ                       (JfTelWf)
  tel-eq  Γ ⊦ Δ ≐ Δ'                  (JfTelEq)
  sp-wf   Γ ⊦ ē : Δ                   (JfSpineWf)
  sp-eq   Γ ⊦ ē ≐ ē' : Δ              (JfSpineEq)

// Differences from NovaSyntax.txt (the complete list — everything else
// above is copied verbatim):
//
//   1. Γ ::= ε | Γ ᐅ x:T                (was `Γ ᐅ T`)
//   2. Δ ::= ε | x:T ◁ Δ                (was `T ◁ Δ`)
//   3. t{5} ::= x | ...                 (was `☐ₙ | ...`)
//   4. T{1}/t{1} Pi/Sigma/Quotient gain inline binder name(s): `(x:A)→B`,
//      `(x:A)⨯B`, `A / (x y. R)`        (was `A → B`, `A ⨯ B`, `A / R`)
//   5. t{2}'s λ and ℕ-elim gain inline binder name(s): `λx. f`,
//      `ℕ-elim z (n ih. s) t`          (was `λ f`, `ℕ-elim z s t`)
//   6. ctx-ext   Γ ᐅ x:T                (was `Γ ᐅ T`)
//   7. el-var    Γ ⊦ x                  (was `Γ ⊦ ☐ₙ`)
//   8. el-quot-elim's `motive` clause gains a name for its bound `q`:
//      `motive (q'. B)`                (was `motive B`)
//
// Every rule keyword, arity, and premise is otherwise identical — this is
// purely a concrete-syntax change to how contexts and compound values are
// written and displayed.
//
// Open questions for the implementation (not yet resolved by this spec):
//
//   - Whether the interactive `apply`/`query` workflow requires (5)/(4)'s
//     inline names to always be spelled out by the AI, or whether writing
//     `_` (or omitting a Pi/Sigma name entirely, per the sugar above) can
//     trigger the tool to auto-fill whatever name the immediately
//     preceding `ctx-ext` already assigned to that exact binder — the
//     latter is recommended (it's what keeps incremental derivation as
//     terse as it is today) but needs the parser to actually track "which
//     ctx-ext produced the context this wrapping rule's premise was
//     derived against."
//   - Δ (backward telescopes, used only by tel-wf/tel-eq/sp-wf/sp-eq) has
//     no incremental "build one entry at a time" rule in R the way Γ has
//     ctx-ext — telescopes only ever appear as fully-formed literals, and
//     by the same self-containedness argument that drove (4)/(5) above, a
//     *dependent* Δ entry referencing an earlier entry's bound variable
//     likely needs the same `x:T ◁ Δ` inline treatment throughout, not
//     just at Δ's own top level. None of the worked derivations
//     (derivations/plus, derivations/vect, derivations/vect-append,
//     derivations/vect-append-assoc) exercise tel-wf/sp-wf, so this is
//     untested — resolve once a concrete telescope-based derivation is
//     attempted.
//   - Identifier lexical syntax (allowed characters, whether primes/
//     subscripts are supported) is left to the parser implementation.
//   - Whether `session.rules`/`session.target` files persist the chosen
//     names on disk (so re-opening a session later doesn't require
//     replaying the whole file to recover them) or names are recomputed
//     transiently by re-running the file — persisting them is recommended
//     since it directly serves the cross-session/cross-agent handoff use
//     case the `derive` skill already relies on, and is close to free once
//     (4)/(5) make every stored compound value self-describing anyway.
