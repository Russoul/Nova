* Use `pack` to type check / build / run idris2 programs
* There is also a Nix flake mirroring `pack.toml`'s pins: `nix build` (the `nova` executable), `nix flake check` (every CI gate), `nix develop` (a shell where `idris2 --build nova.ipkg` works directly). The gate scripts take `NOVA_BIN` / `NOVA_TESTS_BIN` / `NOVA_LSP_BIN` to reuse already-built executables instead of invoking pack
* Use `./test.sh` to run the test suite (passes the required `PATH_TO_SELF` argument automatically); extra golden framework flags (e.g. `--only ty-pi`) can be appended
* To check a Nova surface file, run `build/exec/nova elab <file>.nova` (after `pack build nova.ipkg`): a file is accepted iff the run ends with zero obligations; discharge an obligation by prepending a lemma — an ordinary `def` whose type is the obligation's statement as an equality type — NAMING it in the surfacing item's `using` clause (the report's `hint:` line usually names it for you), and re-running. Discharge is scoped: an item sees only its named lemmas plus hypotheses
* `build/exec/nova distill <file>.nova <out-dir>` renders the file's module closure back to surface text and verifies the round trip (docs/NovaPerfectSurface.txt); `./check-distill.sh` runs it over the whole corpus AND enforces that `src/nova` stays in canonical distill form (byte-identical to its own distillation). Its fix half is `./normalize-corpus.sh` (or `make normalize`): run it after editing corpus files, or after any grammar/printer change, and it rewrites only the files that actually differ
* The theory and its implementation are specified in `docs/`: `NovaFoundation.txt` (the type theory — sole source of truth; official reading intrinsic, semantics the setoid model), `NovaModel.txt` (the standard meta-circular model: the setoid model's code layer), `NovaKernel.txt` (the trusted kernel, rule by rule), `NovaElaboration.txt` (surface syntax + elaborator), `NovaPipeline.txt` (the trust architecture), `NovaPerfectSurface.txt` (the perfect (elaborator, printer) pairing: the distill printer, round-trip contract, sugar tiers). Read the relevant spec before the Idris sources — every function mirrors a documented rule
* The human-facing language reference is `docs/reference/*.md` (a small fixed Markdown subset, documented at the top of `tools/render-reference.py`); `python3 tools/render-reference.py --out build/docs/reference.html` renders the whole book to one page. Chapter ORDER and part titles live in `PARTS` in that script — chapter files are named by slug, never numbered — and a chapter whose second line is `%stub` is an outline, badged as such and counted in the page's progress line. Unlike `docs/*.txt`, it is NOT normative: it teaches the surface language and links into the specs
* The reference QUOTES the sources instead of copying them, and `python3 tools/render-reference.py --check` (a golden test, `tests/nova/docs/reference-snippets`, and a CI step) enforces it: every ```nova block must occur verbatim — contiguous lines, dedented, blank-line-separated chunks matched one by one — in `src/nova` or a golden's `input.nova`; every ```report block in a golden's `expected`; every cited `docs/*.txt`, `src/nova/*.nova` or `tools/*` path must exist; and every backticked rule-shaped token must name a rule `render-specs.py` finds in the specs.
